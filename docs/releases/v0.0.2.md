# AdaptiveLinearSolvers v0.0.2 发布说明

## 1. 发布范围

`0.0.2` 将路线规划与数值执行分离，并把迭代方法及预条件器的数学资格接入规划结果。该版本仍只执行 Julia 标准库的直接路线；迭代方法仅被正确规划和审计，不会被误报为已执行。

## 2. 接口变化

- 新增 `plan(problem, policy)`，返回不具有数值执行副作用的 `RoutePlan`。
- `RoutePlan` 区分 `candidate_routes`、`planned_routes`、`execution_routes` 和 `unavailable_routes`。
- 新增 `PreconditionerContract`，记录预条件器在一次求解内的固定性和线性性证据。
- 新增 `qualify_iterative(problem, method)` 与 `IterativeQualification`。
- `RouteCertificate` 增加分层策略判定和暂不可执行路线信息。

## 3. 数学路线规则

CG（Conjugate Gradient，共轭梯度法）要求已认证 Hermitian 正定性；MINRES（Minimum Residual，最小残量法）要求已认证 Hermitian 性。GMRES（Generalized Minimal Residual，广义最小残量法）要求调用方提供的预条件器在一次求解内固定且线性。若预条件器可变、非线性或其性质未知，GMRES 被拒绝，并由 FGMRES（Flexible Generalized Minimal Residual，柔性广义最小残量法）作为合格候选。

`Lock(:gmres)` 不允许规划器静默改写为另一方法；不满足资格时得到空的可执行路线。`Prefer(:gmres)` 可保留 GMRES 的拒绝记录，并允许 FGMRES 进入合格计划。

## 4. 验证记录

在 Julia `1.12.0` 下运行：

```powershell
julia --project=. -e 'using Pkg; Pkg.test()'
```

结果为 `29/29` 测试通过，耗时约 `5.8 s`。测试覆盖直接路线、数学资格、分层规划、稀疏矩阵、零右端项、秩亏路线、预条件器语义，以及 GMRES/FGMRES 分流。

## 5. 未包含功能

- 不执行 CG、MINRES、GMRES、FGMRES 或 BiCGStab 数值迭代。
- 不提供可应用的预条件器实现。
- 不支持矩阵自由算子、块系统、GPU、MPI、持久化历史或高级诊断遥测。

下一开发批次将接入首个可执行迭代后端，并统一迭代停止、残差、breakdown 和失败监控。
