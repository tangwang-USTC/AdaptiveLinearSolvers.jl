# AdaptiveLinearSolvers v0.0.4 发布说明

发布日期：2026-09-08

`0.0.4` 在 `0.0.3` 的直接与 Krylov 求解基础上，完成了条件数与数值诊断、可观测性与历史自适应，以及资源预算与后端能力登记的首个可执行批次。版本仍处于试验期，不承诺稳定 API。

## 发布范围

### 条件数与数值诊断

`ConditioningInfo` 现在记录条件指标、作用算子、矩阵版本、来源、可靠性与证据。`assess_conditioning` 只验证外部信息；默认 `ConditioningPolicy()` 不估计条件数，也不增加算子应用。只有显式授予时间和维度预算时，`diagnose` 才会在小型显式稠密方阵上执行受限估计。

`NumericalDiagnosis` 分别返回条件状态、迭代状态、预条件器状态与综合状态，避免把近秩亏、停滞、Krylov breakdown、预条件器可疑失效和实际不收敛混为同一原因。版本匹配且可信的近秩亏外部信息可使直接路线优先考虑 `SVD`，但永不绕过数学资格门。

### 可观测性与历史建议

`FingerprintProfile` 逐字段控制指纹；未启用字段为 `nothing` 且不参与检索。`HistoryStore` 提供相似记录查询、候选路线成功率统计、`route_advice` 和预条件器复用提示。历史只能重排已经数学合格且没有被 `Lock` 或 `Prefer` 指定的自动候选路线。

`trace` 与 `diagnostic` 遥测受 `TelemetryBudget` 限制，只截取 Krylov 后端已生成的残差历史，不额外重算残差、谱或条件数。`save_history` 与 `load_history!` 仅在调用方显式指定路径时执行；二进制历史文件只能从受信任本机路径加载。

### 资源与后端

`ResourceBudget` 统一约束时间、迭代次数、内存下界和算子应用上限；资源不满足时返回 `BudgetTerminated` 并记录原因。`BackendPolicy` 与 `backend_capabilities()` 显式登记当前能力：`LinearAlgebra` 直接法和 `Krylov.jl` 仅在串行 CPU 上实现。

`IterativeSolvers.jl`、`LinearSolve.jl`、PETSc、CUDA 与 MPI 只作为未实现适配器登记，不能因名称匹配而自动使用。后续接入必须完成输入适配、统一状态映射、预条件器语义测试和对应设备或分布式环境验证。

## 已知边界

- 条件数估计当前只支持预算内的小型显式稠密方阵；稀疏与矩阵自由大系统只接受外部信息或返回未执行原因。
- 历史持久化采用 Julia `Serialization`，不作为跨版本、跨语言交换格式。
- 内存预算仅使用当前后端可得的保守下界；稀疏直接法 fill-in 未知时会拒绝有界内存请求。
- GPU、MPI、PETSc、LinearSolve.jl 和 IterativeSolvers.jl 尚无可执行适配器。
